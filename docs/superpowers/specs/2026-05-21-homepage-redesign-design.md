# 首页(Landing)重设计 设计文档

> 日期:2026-05-21
> 范围:首页 `/`(`apps/web/src/app/page.tsx`)
> 状态:已通过 brainstorming,待用户确认

## 1. 背景与问题

当前首页 `/` 存在两个根本问题:

1. **认不得人** —— 对登录用户和未登录访客显示完全相同的内容。已经填过分数、存过方案的老用户回到首页,看到的还是面向陌生人的宣传内容。
2. **大量写死的演示数据,损害信任** —— Hero 右侧假位次卡、"真实案例"假志愿、"数据底座"假"92% 匹配度"、CTA 区假用户量("12,408 名考生"等)。对一个承载高考志愿这种重大决策的产品,编造的社会证明是诚信风险。

## 2. 目标与范围

把首页 `/` 重构为**双形态首页**:

- **未登录访客** → 看 landing(宣传 + 建立信任 + 引导注册)
- **登录用户** → 重定向到对应角色工作台

**本次范围**:重设计 landing(未登录视图)+ 登录态重定向逻辑。

**范围之外**:

- 三个角色 dashboard(`/student/dashboard`、`/teacher/dashboard`、`/admin/dashboard`)的任何改动 —— 它们已是完整功能。
- 其他页面(`/universities` 等),后续逐页进行。
- 让推荐引擎为示例考生实时生成真实方案(已确认不做)。

## 3. 整体架构:双形态与重定向

访问 `/` 时按登录态与角色分流:

| 状态 | 行为 |
|---|---|
| 未登录 | 显示 landing |
| 已登录 · STUDENT | 重定向 → `/student/dashboard` |
| 已登录 · TEACHER | 重定向 → `/teacher/dashboard` |
| 已登录 · ADMIN | 重定向 → `/admin/dashboard` |

- 重定向**优先在 middleware 实现**(项目已有 middleware 做角色判断),避免先渲染 landing 再跳转的闪烁。
- 若 middleware 无法直接拿到角色,则在首页组件用 `useAuthStore` + 客户端重定向兜底。
- 角色判断异常时,默认显示 landing(往安全侧兜)。

## 4. Landing 结构

原 8 个 section 精简为 **5 个**:

| # | 区块 | 来源 |
|---|---|---|
| 1 | Hero 区 | 原 Hero(改造) |
| 2 | 产品能力区 | 合并原"三步走" + "核心能力 6 卡片" |
| 3 | 方案示例区 | 原"真实案例"(改造) |
| 4 | 结尾 CTA 区 | 原 CTA 区(改造) |
| 5 | 数据来源条 | 原第 2 块"数据来源条",移到最底部 |

**移除的 section**:原"数据底座"StatCard 区(统计与 Hero 重复 + 含假数据)、原独立"填报流程时间线"section(内容上移进 Hero)。

## 5. 各区块详细设计

### 区块 1 · Hero 区

**左侧**

- 主标题改为藏头联:**「智者明察 洞见四方 / 愿展宏图 扶摇直上 / 家有良师 伴你远航」**(首字"智 / 愿 / 家"金色 + 着重号,藏头"智愿家")
- 去掉左上角的 `CountdownBadge` 小倒计时徽章(与右侧新卡的大倒计时重复)。
- 保留:eyebrow、副文案、两个 CTA(免费开始智能推荐 / 浏览在川招生院校)、4 个统计(2,237 院校 / 14.4 万录取 / 1,434 专业 / 4 年)。
- 4 个统计是真实数据,用前端常量维护。
- 副文案承担"智慧 / 数据 / AI"卖点的表达(原副文案已讲数据 + AI,沿用或微调)。

**右侧** —— 假位次卡 → **志愿填报时间线卡**

- 内容:卡片标题(如"2026 四川志愿填报时间线")+ 大倒计时"距高考 XX 天" + 关键节点列表。
- 节点(物理类 / 历史类一致):
  1. 6/7–9 · 高考
  2. 6/23 前后 · 出分 · 一分一段表
  3. 6/28 17:00 · 本科提前批志愿截止
  4. 7/1 17:00 · 本科批(其余本科)志愿截止
  5. 7/5 17:00 · 专科批(含专科提前批)志愿截止
- 进行中 / 最近的节点高亮。
- 数据来自 `timelineApi`。
- **移动端必须可见** —— 原卡片用 `md:block` 在手机端隐藏;新卡承载倒计时这种关键信息,移动端要保留(可用精简形态)。

> 批次截止时间来源:四川省教育考试院 2026 年志愿填报安排(sceea.cn)。

### 区块 2 · 产品能力区(合并)

由原"三步走" + "核心能力 6 卡片"合并为一块。

- 流程主线:**查分定位 → 研究院校与专业 → AI 推荐并打磨志愿表**。
- 5 个核心功能入口卡:院校库、专业库、查分系统、AI 推荐、方案编辑器(对应导航栏 5 个功能页)。
- **去掉原"数据安全"卡** —— 它不是功能而是信任声明,移到区块 4 用一行小字体现。

### 区块 3 · 方案示例区(原"真实案例")

- 改名,不再用"真实案例"(如"一份志愿方案长什么样")。
- 顶部明确标注:**"以下为示例演示,注册后将基于你的真实分数和偏好生成"**。
- 内容保留:展示一份方案的形态(冲 / 稳 / 保梯度 + 若干志愿条目),让访客直观理解产品产出。"628 分"作为具象示例保留,定性为示意。

### 区块 4 · 结尾 CTA 区

- 保留:左侧标题、副文案("免费注册…无广告,无诱导消费")、两个 CTA。
- **删除**右侧假用户量("12,408 名考生 / 21 个市州 / 832 所中学")。
- 右侧删空后,CTA 区改为**单栏居中**。
- 从区块 2 移来的"数据安全"信息,在此用一行小字体现。

### 区块 5 · 数据来源条(底部)

- 位置:从原第 2 块移到 landing **最底部**(页脚上方)。
- 内容不变:四川省教育考试院、阳光高考信息平台、各高校招生办、2022-2025 录取年报、"持续更新"。
- **加超链接**(可点击跳转):
  - 四川省教育考试院 → `https://www.sceea.cn`
  - 阳光高考信息平台 → 教育部阳光高考平台官网
  - "各高校招生办""2022-2025 录取年报"非单一网址,保持纯文本。

- CTA 区假用户量(12,408 考生 / 21 市州 / 832 中学)

- 原"数据底座"section(统计与 Hero 重复)
- 原独立"填报流程时间线"section(内容并入 Hero 时间线卡)
- 原"三步走"与"核心能力"二者合并

**内部实现说明**

- 删除"填报流程"原副标题里"没有数据时使用设计稿默认流程展示"这类暴露给用户的内部说明。

## 7. 数据流与接口

- landing 唯一数据接口:`timelineApi.getTimeline(year)` → Hero 时间线卡。
- 后端时间线数据需包含第 5 节所列 5 个节点(含 3 个批次截止)。若后端暂无批次截止 event,需补充录入,由 `timelineApi` 统一下发,前端不写死。
- Hero 4 个统计使用前端常量(变化慢,一年一更)。
- 其余区块(产品能力、方案示例、CTA、数据来源)均为静态内容,无接口。

## 8. 错误处理与兜底

- `timelineApi` 拉取失败 → Hero 时间线卡使用前端 fallback 数据(沿用现有 fallback 机制,把 5 个节点含批次截止写进 fallback)。
- 角色判断异常 → 默认显示 landing。

## 9. 验证

- **重定向**:未登录访问 `/` 看到 landing;STUDENT / TEACHER / ADMIN 登录后访问 `/` 分别落到对应工作台。
- **时间线卡**:正常显示倒计时 + 5 个节点;`timelineApi` 失败时 fallback 生效;手机端可见。
- **假数据**:确认假位次卡、假案例、92% 匹配度、假用户量已全部从页面移除。
- **结构**:5 个区块顺序与内容正确;数据来源条在底部且链接可点击跳转。
