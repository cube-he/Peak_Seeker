# 数据校验规则清单（2026-04-17）

> 所有 2025 征集志愿/招生计划 xlsx 校验 pilot agent **必须**在读图核对前阅读并遵守本文件。
>
> 来源：4413 Pilot v1 → v2 修正中提炼。

## Rule 1：括号归属判别规则

**判别依据**：**报纸原文印刷版式**（图片），不是引擎 xlsx 输出。

### 1.1 归属专业备注的括号

以下内容出现在括号中时，**无论引擎输出在哪一列，最终都应落到「专业备注」**：

| 类别 | 示例括号内容 |
|---|---|
| 地点 | `(雅安市)`、`(凉山州)`、`(乐山市)`、`(阿坝州)` |
| 校区 | `(宜宾校区)`、`(江北校区A区)`、`(新都校区)` |
| 培养地点 | `(预科培养地点为四川民族学院。)`、`(预科培养地点为西昌学院。)` |
| 任教地区 / 定向就业地区 | `(任教地点为XXX)`、`(就业地区为XXX)` |
| 方向说明（如报纸作独立段排版） | `(师范)`、`(定向XX县)` |
| 专业备注本身（报纸用前缀显式标识） | `(专业备注:XXX)` |

### 1.2 归属专业名称的括号

以下内容应**保留在「专业名称」列**：

| 类别 | 示例 |
|---|---|
| 子专业 / 内涵说明（专业本体的一部分） | `少数民族预科(应用心理学)`、`少数民族预科(护理学)`、`少数民族预科(旅游管理)` |
| 学科方向（视原文排版紧贴专业名） | `计算机类(智能科学与技术方向)` |

### 1.3 判别决策树

```
看报纸图片原文：
├─ 括号紧贴专业名印刷，无空格分隔，且内容是子专业/方向？
│   └─ YES → 专业名称
└─ 括号作独立段列出（有空格或换行分隔），内容为地点/校区/培养地点/备注前缀？
    └─ YES → 专业备注
```

### 1.4 多个并列括号

当一行内有多个括号（如 `47 汽车服务工程(乐山市)(宜宾校区)(专业备注:入学后不允许跨校区转专业。)`），按上述规则**逐个判别**：
- 专业名称 = `汽车服务工程`
- 专业备注 = `乐山市；宜宾校区；入学后不允许跨校区转专业。`（分号串接）

### 1.5 合并多条备注到一列的格式

多个备注合并到「专业备注」时用 `；`（中文分号）分隔。末尾保留原文句号。

## Rule 2：招生类型前向填充（Forward-Fill）

### 2.1 场景

征集志愿/招生计划正文中，「招生类型」通常是**分节小标题**（如 `1. 区域教育均衡发展专项计划` / `2. 省属高校少数民族预科` / `普通类` / `国家专项计划` / `地方专项计划` / `高校专项计划` / `中外合作办学` / `民族班`）。当同一招生类型下的数据跨页时，**后续页面不会再印刷该标题**，但 xlsx 的「招生类型」列必须继承前一节的值。

### 2.2 Agent 处理步骤

1. 按图片页序扫描，记录每次出现的"招生类型"小节标题及其页号/起始位置。
2. 为每一行数据标注"它属于最近一次出现的哪个小节标题"。
3. 跨页行自动继承上一节的招生类型值。
4. 如果 xlsx 中某行的"招生类型"与推断值不同，**不要信任 xlsx**，以图片推断为准。

### 2.3 引擎 Fallback 陷阱 ⚠️

**已观察到的引擎行为**：当引擎在页面开头没看到小节标题时，它倾向于 fallback 到 `普通类`。**但 `普通类` 在大多数征集志愿/专项/预科批次中根本不存在**。

**强制检测**：凡是 xlsx 中出现 `普通类` 的行，agent 必须**回图核对**；如果图片该节未印"普通类"字样，必须替换为正确的继承值。

### 2.4 枚举参考

2025 四川批次常见招生类型枚举（非穷尽）：
- `普通类`
- `国家专项计划`
- `地方专项计划`
- `高校专项计划`
- `区域教育均衡发展专项计划`
- `省属高校少数民族预科`
- `中外合作办学`
- `民族班`
- `定向培养军士`
- `免费医学定向`
- `公费师范生`

## Rule 3：科类前向填充（Forward-Fill）

同 Rule 2 逻辑，适用于「科类」列。

### 3.1 场景

图片中「一、历史类」「二、物理类」是大节标题。跨页后续行继承上一节值。

### 3.2 枚举

- `历史类`
- `物理类`
- （旧高考旧样本：`文科` / `理科`，2025 年后不再出现）

### 3.3 Agent 自检

完成校验后必须跑"科类覆盖自检"：
- 统计图片中出现的科类关键词（正则匹配 `一、?\s*历史类` / `二、?\s*物理类`）
- 与 xlsx 中 `科类` 列的 distinct 值对比
- 不一致 → 必有漏行或误标，回图核对

---

## Rule 4：图片权威优先

所有校验必须以**图片原文**为最终真值源，优先级：

```
图片原文 > corrected 版本 > mimo-v2-omni 原版
```

- 两版引擎分歧时，看图片裁定。
- 两版引擎一致但与图片冲突时，按图片修正（mimo/corrected 都可能系统性错）。
- v1 verified 也可能有错（如本次 4413 的 Rule 1/Rule 2 错误），**不能基于 v1 递推 v2**，必须重读图片。

---

## Rule 5：整行缺失检测（Row Coverage）

### 5.1 已观察到的 mimo-v2-omni 问题

引擎对跨节数据识别弱，整行漏扫。例如 4413 中 mimo 漏了历史类 2 行 Y5/Y8 预科。

### 5.2 Agent 自检方式

- 按图片逐页数行（院校代码+专业代码粒度）
- 与 xlsx 行数对比
- 差值 ≠ 0 → 必补齐

---

## Rule 6：四方差异追溯

v2 及之后的 verified xlsx 必须保留四方对照：
- `mimo-v2-omni原值`
- `corrected原值`
- `v{N-1}_verified值`（前一版真值，如果有）
- `v{N}最终真值`

修改记录 Sheet 的每条记录必须能定位到**图片路径 + 图片行号/位置**，便于人工快速复核。

---

## Rule 7：颜色标注规范

| 颜色 | 含义 |
|---|---|
| 🟡 Yellow (`#FFFF00`) | 前一版（如 v1）已修，本版（v2+）沿用 |
| 🟠 Orange (`#FFA500`) | 本版相对前版**新修**的 delta 单元格 |
| 🔴 Red (`#FF6666`) | 图片分辨率不足/模糊，人工复核待定 |
| 无色 | 引擎原值与图片一致，无需修改 |

---

## Rule 8：Agent 输出要求

1. **不覆盖旧版**：每版 verified 用独立文件名（`_verified.xlsx` / `_verified_v2.xlsx` / ...），保留对比。
2. **3 个固定 Sheet**：`真值数据` / `修改记录` / `引擎差异`
3. **修改记录可追溯**：每行记录必须含图片路径字段，例 `4413_003.jpg`
4. **脚本可复现**：把真值硬编码在脚本 GT 列表，运行后打印 yellow/orange/red 计数
5. **报告可追加**：同一批次的多轮 pilot 追加到同一份 MD 而非新建（避免散落）

- [ ] 已检查 xlsx 中的"普通类"字样是否都对应图片中印刷的"普通类"（Rule 2.3）
- [ ] 已对比图片行数 vs xlsx 行数（Rule 5）
- [ ] 已在修改记录中保留图片路径（Rule 6）
- [ ] 已按规范用 Yellow/Orange/Red 三色（Rule 7）
- [ ] 已保留前版 xlsx 不覆盖（Rule 8）
