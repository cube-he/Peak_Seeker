# 学生端

## 概述

面向考生/家长的查看和基础自助端。移动端优先设计。

## 数据模型引用

- StudentProfile, VolunteerPlan, PlanItem, PlanShareLink

## 页面结构

```
/student（移动端优先）
  /dashboard            首页（方案进度可视化+最新通知）
  /profile              个人信息（渐进式表单+完整度进度条）
  /plans
    /list               按批次分组，模拟/正式标签区分
    /[id]               方案详情（通俗解读+确认/提疑问）
  /recommend            轻量自助推荐
  /filing
    /upload             上传填报截图
    /result             录取结果查看
  /browse               院校/专业浏览
  /favorites            收藏（同步到老师端可见）
```

## 轻量自助推荐

不做系统抽样，不出55个志愿组。
输入分数 → 推算位次 → 按位次范围筛选 → 评分排序 → Top30
按冲/稳/保三组展示
引导："想要完整方案？联系你的老师"

## 方案查看

学生看到老师发布的定版方案：
- 结果表24列完整展示（通俗解读层叠加）
- 备选池可查看
- 版本历史
- 老师备注

**通俗解读层**：
- 老师看："高冲志愿，位次差-12000" → 学生看："冲刺选择，需要运气，发挥好有希望"
- 老师看："干净度🟡混编(3个慎选)" → 学生看："8个专业中5个前景不错，建议服从调剂"

**不可操作**：不能修改/删除/生成方案

## 参与机制

- 确认/提疑问：不能改方案，但能反馈给老师（触发通知）
- 收藏院校/专业：同步到老师端，老师可参考
- 进度追踪：可视化 采集中→生成中→审核中→已定版→待填报

## 方案进度标签

examSource 区分：
- [二诊预案] 灰色/蓝色标签
- [高考正式] 绿色/金色标签

## 免责声明

方案详情页顶部固定：
"本方案由老师基于历年数据和算法模型生成，仅供参考。
 最终填报请以官方招生章程和考试院公布的招生计划为准。"

## UX 要点

- 移动端优先，所有交互适配小屏
- 信息要通俗，避免专业术语
- 进度感：让学生知道"我的方案走到哪一步了"

## 测试要点

- 权限隔离：学生只能看自己的方案
- 分享链接：无登录访问+过期失效
- 移动端响应式：主要页面在375px宽度下可用
