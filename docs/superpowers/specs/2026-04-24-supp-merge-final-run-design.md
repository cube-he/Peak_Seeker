## 二、相对 v5 的增量变更

### 2.1 业务规则调整：三类 WARN 降级为 INFO

v5 §7 一致性校验中，以下三类判定为 WARN，本轮**降级为 INFO**（仅审计留痕，不计入需修复清单，不作为质量门禁）：

| 原 v5 级别 | 新级别 | 名称 | 原因 |
|---|---|---|---|
| WARN | INFO | 计划数递增 | 院校可合法新增/调增计划 |
| WARN | INFO | 征集超计划 | 同上（业务合法） |
| WARN | INFO | 轮次断档 | 专业可在第 N 轮首次参与征集，第 1~N-1 轮无数据是合法现象 |

代码改动点：`p5_merge_supplementary.py` 中 `check_consistency` 相关函数，把这三类日志写入时 `severity = "INFO"`。

### 2.2 质量门禁收紧

本轮最终交付前必须满足（不达标则回修、不推进下一阶段）：

| 指标 | 本轮目标 | v5 实际 |
|---|---|---|
| ERROR-重复写入 | **= 0** | 355（必须全部清零） |
| KEY-INCOMPLETE | ≤ 50 | 305（定位源头消除） |
| WARN-名称多命中 | ≤ 50 | 198 |
| WARN-去类型多命中 | ≤ 5 | 13 |
| 抽样 100 条 × 逐字段准确率 | ≥ 99% | 未做 |

**未匹配率**不作为硬门禁——v5 已分析 80% 未匹配是真实数据缺口（23-24 停招专业、主表无对应 2025 行），算法不可修复。本轮维持"未匹配入孤立表、不入主表"策略。

### 2.3 ERROR-重复写入 清零策略

v5 出现 355 条重复写入（同 `(行号, 年份, 轮次)` 被多个文件写入），逐类处理：

| 根因 | 处理 |
|---|---|
| 2025 映射表多候选命中同一主表行（如 A段/B段同匹配） | 加二次筛选键（专业组代码 + 招生类型精确相等） |
| 源数据 OCR 重复（同一行被识别两次） | 在 `_已校验.xlsx` 中去重（同院校+专业+轮次） |
| 主表某行匹配键组合非唯一 | 专家确认后在主表标注 `__multi_key__`，合并时跳过 |

不做"累加"或"首个生效"——必须逐条判定根因。

### 2.4 抽样准确率验证（新增 Phase）

v5 仅有 30 条随机抽样。本轮升级为：

- 随机抽 **100 条**已写入记录，按批次分层抽样（2023/2024/2025 各 ~33 条）
- 派 **5 个 Opus 4.6 子 Agent**（每 Agent 20 条）并行，回到源 `_已校验.xlsx` 做逐字段比对
- 校验字段：院校代码、专业代码、专业名称、科目、招生类型、计划数、收费、备注
- 输出 `征集抽样准确率报告.xlsx`，准确率 <99% 则回到 Phase C 做根因修复

## 六、风险与应对

| 风险 | 应对 |
|---|---|
| ERROR-重复写入无法清零（主表键非唯一） | 与专家确认后在主表增加标记列 `__supp_skip__=1` 让合并跳过 |
| 抽样准确率 <99% 且根因定位不到 | 立即暂停合并，不覆盖主表，产出诊断报告交付用户决策 |
| 主表文件被其他流程并发改写 | 合并前 sha256 校验，前后一致才覆盖 |
