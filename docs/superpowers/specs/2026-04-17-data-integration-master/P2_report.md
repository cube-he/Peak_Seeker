### 2.3 差异报告（P2.3）

`both` 11,133 行 × 10 个重叠字段 = **19,495 条字段级差异 / 492 条 anomaly（2.5%）**

| 字段 | Anomaly 数 | 类型 |
|---|---:|---|
| 录取人数 | 189 | count |
| 最低位次 | 86 | rank |
| 最高分 | 65 | score |
| 最低分 | 65 | score |
| 平均分 | 48 | score |
| 计划人数 | 39 | count |
| **合计** | **492** | |

**ISSUE-014 已解决**：前版 anomaly 率 57.3%（17,328/30,267），经根因分析发现 97.2% 来自 01 端 partial-data 行（`enterNum>0` 但分数/位次留 0 占位）。修复：`source_01` 加载时把分数/位次字段的 0 归一为 NaN，走"一侧空"分支（入 field_fill 补缺通道，不算 anomaly）。录取人数/计划人数 的 0 保留（"计划未录取"属真实语义，确实是 03 vs 01 分歧信号）。

修复后 anomaly 从 17,328 → 492（-97%）。

产物：
- `data/_pipeline/P2/cross_diff_report_2025.xlsx`（19,495 行）
- `data/_pipeline/P2/anomaly_diff_2025.xlsx`（492 行，按 |差值| 降序）

## 4. 技术决策（已落地，不需要用户介入）

| ID | 议题 | 决策 | 理由 |
|---|---|---|---|
| D1 | 位次字段 anomaly 率异常高 | 修复 `source_01`：分数/位次 0 值归 NaN | 根因分析显示 97% 来自 01 partial-data，非口径差异 |
| D2 | `new_rows` 7362 条入库策略 | **不自动合入 03**，作为 P4 阶段候选 | ADR-001：03 = SSoT；`new_rows` 需结合 03 侧人工核验（部分可能是 01 录入错误） |
| D3 | `field_fill` 291 条补字段策略 | **仅保留 `_01` 列 + `_backfill_notes` 注释，不写入 03 原字段** | ADR-003：不覆盖 03；下游消费方可按需取 `_01` 值 |
| D4 | 抽样中出现 `最高分=0 / 录取人数=7→0` 漏网 | D1 修复顺带解决分数类；录取人数 `0` 保留（是真实的"计划未录取"，构成有效 anomaly 信号 `106541/W2` 等） | 区分占位 vs 真实零值 |
