# DECISIONS（ADR 决策记录）

每条决策按 ADR 格式：状态 / 背景 / 决策 / 后果。

## ADR-001：以 03 为唯一事实主源

- **状态**：已采纳（2026-04-17）
- **背景**：03 是人工整合多源的成果，01 是官方原始数据，13 是 OCR 产物。若三者并列，冲突时无所适从
- **决策**：03 = SSoT；01 仅补缺 + 校验；13 独立治理后再合入；任何整合不得覆盖 03 既有非空值
- **后果**：
  - ✅ 决策边界清晰，冲突处理有标准
  - ✅ 与历史教训对齐（01 缺提前批、字段翻转，不适合作主源）
  - ⚠️ 若 03 某字段本身有错，依赖交叉校验发现

## ADR-002：不直接入库，先出中间文件

- **状态**：已采纳（2026-04-17）
- **背景**：历史尝试 L2 直接写 DB，scripts/import-data/import-enriched.ts 出 BUG 后难回滚
- **决策**：每阶段产出 xlsx/csv/parquet 中间文件，用户肉眼验收后再考虑入库
- **后果**：
  - ✅ 可回滚、可审计、可并行验收
  - ⚠️ 入库任务推迟到本 spec 之外

## ADR-003：01 独有字段作新增列而非替换

- **状态**：已采纳（2026-04-17）
- **背景**：01 有独家字段（位次、征集标志、压力线），03 部分年份也有位次
- **决策**：01 字段列名加 `_01` 后缀作新增列；若 03 对应字段空则在差异报告中标注"补缺候选"
- **后果**：
  - ✅ 数据血缘清晰
  - ⚠️ 列数增加，需要在数据字典明确区分

## ADR-004：13 OCR 错误率必须先量化再修

- **状态**：已采纳（2026-04-17）
- **背景**：历史尝试直接上修复脚本，未知错误率，修完不知道效果
- **决策**：P3.3 强制先抽样 200 条对原图比对，量化分类错误率，再做修复
- **后果**：
  - ✅ 修复策略有针对性，效果可评估
  - ⚠️ 增加 P3 工时

## ADR-005：本科批模糊 7 条暂标保守值

- **状态**：已采纳（继承 2026-04-17 历史决策）
- **背景**：rename plan 中 7 个条目无法从 xlsx 找到"本科一批/二批控制线"字样
- **决策**：保守标为 `本科批_一二批混合`，P3 阶段由人工复核公告图后定论
- **后果**：
  - ✅ 不误标
  - ⚠️ 需要在 P3 增加人工复核环节
