## 执行中发现的问题

### ISSUE-007：batch_dict 错误诊断可定位性不足
- **发现时间**：2026-04-17（Task 3 code review）
- **影响阶段**：P2（跨源 normalize 时）
- **描述**：`normalize_batch_name` 当 `(year, course)` 组合不在 `_CANONICAL_NAMES` / `_ALIASES` 中时，统一抛 `未知批次`，掩盖了"字典本身缺该年份/科目"的根因
- **影响**：P2 跨源校验若传入未注册组合（如 `2023/理科`），报错信息误导
- **解决方案**：P2 开工前为 `normalize_batch_name` 增加"字典缺失"专用异常路径，并补测试用例
- **状态**：已登记，P2 前修复

### ISSUE-010：03 主表实际已干净 — 审计报告数值过时
- **发现时间**：2026-04-17（Task 9 真实数据 dry-run）
- **影响阶段**：P1（实际）/ P2（简化）
- **描述**：P1.2-P1.4 脚本在真实 03 主表上 dry-run 结果：0 重复 / 0 分数异常 / 2 专业代码缺失；对比 plan 引用的审计报告预期 34 重复 / 232 分数异常
- **根因**：`data/03_专家版主表/output/专业招生主表.xlsx` 是已经过人工整理的 output 产物，审计报告数据基于更早版本
- **影响**：
  - ✅ 正面：验证 ADR-001（03=SSoT）前提成立，数据质量确实比 01/13 高
  - ✅ 正面：代码 fixture 验证三类修复逻辑都工作正常，当新数据入库时自动生效
  - ⚠️ P2 scope 可收紧：01→03 的交叉校验主要用途从"补缺"变为"双向审计 + 追加 01 独有字段"
- **解决方案**：P2 开工前重新评估交叉校验优先级；不修改 P1 代码（防御性逻辑保留）
- **状态**：已登记，P2 scope 调整

### ISSUE-009：CodeMapper 重复映射静默覆盖
- **发现时间**：2026-04-17（Task 4 code review）
- **影响阶段**：P2.1
- **描述**：`CodeMapper.from_csv` 若治理表同一 `national_code` 出现多次，后者覆盖前者无告警；`add_patch` 亦无冲突检测
- **影响**：P2.1 做 01↔03 交叉校验时，治理表若存在历史重复可能 silent data loss
- **解决方案**：P2.1 前加 `conflicts: list` 收集 + WARNING 日志，或 `add_patch(overwrite=False)` 默认严格
- **状态**：已登记，P2.1 前复核

### ISSUE-008：batch_dict 隐式"本科批→B段"默认映射
- **发现时间**：2026-04-17（Task 3 code review）
- **影响阶段**：P2
- **描述**：`_ALIASES[("2025","物理")]` 的 `"本科批": "本科批B段"` 基于假设"无段别时默认 B 段（主体最大）"。若某年/某数据源的"本科批"实际指 A 段或 A/B 合并，会被静默错误映射
- **影响**：P2 批次对齐可能产生跨年跨源的 silent drift
- **解决方案**：(a) 在 P2 首次出 conflict report 时按年份核对真实语义；(b) 若发现歧义，加 `strict=True` 参数禁用模糊默认 + 测试覆盖歧义别名
- **状态**：已登记，P2 首次跑 conflict report 时复核
