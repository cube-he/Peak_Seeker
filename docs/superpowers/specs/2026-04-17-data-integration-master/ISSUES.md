### ISSUE-009：CodeMapper 重复映射静默覆盖
- **发现时间**：2026-04-17（Task 4 code review）
- **影响阶段**：P2.1
- **描述**：`CodeMapper.from_csv` 若治理表同一 `national_code` 出现多次，后者覆盖前者无告警；`add_patch` 亦无冲突检测

### ISSUE-008：batch_dict 隐式"本科批→B段"默认映射
- **发现时间**：2026-04-17（Task 3 code review）
- **影响阶段**：P2
- **描述**：`_ALIASES[("2025","物理")]` 的 `"本科批": "本科批B段"` 基于假设"无段别时默认 B 段（主体最大）"。若某年/某数据源的"本科批"实际指 A 段或 A/B 合并，会被静默错误映射
- **影响**：P2 批次对齐可能产生跨年跨源的 silent drift
- **解决方案**：(a) 在 P2 首次出 conflict report 时按年份核对真实语义；(b) 若发现歧义，加 `strict=True` 参数禁用模糊默认 + 测试覆盖歧义别名
- **状态**：✅ 已修复（commit f718cc7，AmbiguousBatchError + strict 参数 + _AMBIGUOUS_ALIASES 集合）

### ISSUE-013：03 是宽表（年份前缀列），spec 假设的长表 PRIMARY_KEY 不成立
- **发现时间**：2026-04-17（Task 7 开工前 schema 核查）
- **影响阶段**：P2.2 / P2.3 / P2.4（全部 outer join 相关）
- **描述**：03 主表实际结构与 spec 假设不符
  - spec: `(年份, 院校代码, 专业组代码, 专业代码, 批次, 科目)` 是主键，每条记录一个年份
  - 实际: 03 每行代表 (院校, 专业, 批次, 科目) 的**跨年快照**，包含 `25最低分/24最低分/23最低分/22最低分` 等年份前缀列；`数据年份` 列统一为 2025
- **各年有效行数**（据 `XX最低分` 非空）：2025/13116，2024/34312，2023/30775，2022/27091
- **批次/科目口径**：
  - 03 的 `批次` 列是 2025 新高考口径（本科批A/B段 / 专科批次 / 艺体类本科 等）
  - 03 的 `科目` 列只有 `物理/历史`（新高考）；01 历史年份用 `理科/文科`
  - 历史年份数据挂在 2025 批次/科目标签下：需要 `物理↔理科` / `历史↔文科` / 2025 批次名 ↔ 本一/本二 的双向映射
- **解决方案**：
  - 新增 `lib/source_03.py::load_master_long(years)` 把 03 宽表 melt 到长表
  - 每个 (年份, 院校, 专业, 批次, 科目) 一行，年份前缀列去前缀后成为标准列名
  - 首轮 P2.2 **只做 2025 join**（批次/科目口径一致，风险最低），产出 2025 版 enriched
  - 2022-2024 多年合并在 **Task 7b** 单独处理，需 `批次反向映射字典`（2025 口径 → 历史口径）+ `科目转换`（物理↔理科）
- **状态**：已登记，Task 7 scope 调整为 "2025 only"；Task 7b 追加至计划

### ISSUE-012：01 vs 编码映射表 真实覆盖率 94.56%（远低于 spec 假设 99.37%）
- **发现时间**：2026-04-17（Task 6 probe 真实数据）
- **影响阶段**：P2.1 / P2.2 / P2.4
- **描述**：02 跨 2022-2025 四年的 01 数据中 2299 个 unique 国标代码，编码映射表_招生代码_国标代码.csv 只能覆盖 2174 个，125 个无映射
- **分布**：2022 缺 118 / 2023 缺 82 / 2024 缺 58 / 2025 缺 22（逐年改善 → 老年份淘汰院校多）
- **典型缺失**：北京邮电大学(宏福校区) / 赤峰学院 / 江苏警官学院 / 湖州师范学院 / 闽江学院 / 重庆三峡学院 / 陕西工业职业技术学院 等——多为省属/艺术/职业类院校
- **排除假设**：
  - ❌ 不是 5-vs-6 位 zfill 问题（已在 commit de26190 修复，只找回 2 个）
  - ❌ 不是 6-digit 变体（末尾去 1 找 5-digit base：0 match）
- **根因**：治理表实际只覆盖"主流 2215 所院校"，非 spec 假设的"99.37% 全覆盖"
- **影响**：
  - P2.1 手工补全 scope 从 0.63%（~14 条）→ 5.44%（125 条）
  - P2.2 这些码不能桥到 03（因为 03 就在 2215 所之内）→ 归入 `right_only`（01 独有）
  - P2.4 这 125 所院校在 01 专业分数线中的记录可作"补缺候选"加入 03 主表
- **决策**：**P2.1 scope 调整 — 不手工补全 125 条**。改为：
  - (a) `missing_college_codes.csv` 保留作追踪清单
  - (b) P2.2 outer join 时让这些码走 `right_only` 路径
  - (c) P2.4 enrich 时把这些院校作为独立"新增行"处理，标注来源=01
  - (d) 如用户后续要求完整桥接，再派子 agent 手工 web search（另起工单）
- **状态**：已登记，P2.1 scope 调整确认

### ISSUE-011：01 2025 存在大量 minScore=0 空录取记录
- **发现时间**：2026-04-17（Task 4-5 source_01 真实数据 smoke）
- **影响阶段**：P2.3（差异报告）、P2.4（独有字段）
- **描述**：`data/01_核心录取数据/专业分数线_四川_2025.json` 44986 行中 26569 行（59%）minScore/maxScore/avgScore/uMinScore 全为 0、enrollCount/planCount 均为 None。按批次分布：专科批 14021 + 本科B 10911 + 本科A 各段合计 ~1600
- **根因**：推断为"招生计划未产生实际录取"的占位记录（2022-2024 各年仅 ~1000 行 0 分，2025 显著激增）
- **影响**：
  - P2.3 差异报告：0 分 vs 03 真实分数会被误判为"巨大差异"
  - P2.4 独有字段合入：这些行作为 01-only 行合入 03 会污染主表
- **解决方案**：
  - `source_01` 加 `drop_empty=True` 参数（默认开启），丢弃 `minScore==0 and enrollCount is None` 的行
  - 或在 loader 统一把 `minScore==0 and enrollCount is None` 的分数字段改为 NaN，保留行但让差异检测走 null 分支
- **状态**：待 P2.3 前决策取哪种策略
