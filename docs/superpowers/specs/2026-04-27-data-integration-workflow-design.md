## 权威性优先级

```
01_核心录取数据（API）> 02_全国基础库（采集）> 03_专家版主表（网购）
```

冲突时不自动覆盖，输出冲突报告供人工抽查审核。

## 四步整合流程

### Step 1: Layer 2 院校注册表

**目的：** 建立 school_registry.json（2237 所院校 × 10 分组）

**数据源优先级：**
1. 02/院校库_全国 → 基础字段（省份、城市、类型、办学性质、隶属部门等）
2. 02/大学排名_全国 → rankings 分组（QS、USNews、校友会等多维排名 + Logo/Banner）
3. 02/学科评估_全国 → academics.assessmentGrade / assessmentSummary
4. 02/招生章程结构化_2025 → admissionRules 分组（调档比例、专业分配、体检等 11 字段）
5. 02/院校满意度_全国 → satisfaction 分组
6. 03/A 李老师专家版 → 补充 02 缺失的字段（保研率、硕博点专业列表、转专业情况等）

**匹配键：** 院校代码（4 位）

**冲突处理：** 02 和 03 对同一字段有不同值时，输出冲突报告。

### Step 2: Layer 3 招生数据 · 结构骨架

**目的：** 从官方招生计划建立每条记录的骨架（院校 + 科类 + 批次 + 专业组 + 专业）

**数据源：**
1. 01/普通批招生计划_四川_2025 (9678 行)
2. 01/提前批招生计划_四川_2025 (21941 行)

**处理：**
- 批次名归一化 → 通过 batch_mapping 映射到 batchNodeId
- 建立 enrollment → group → major 层级骨架
- 填入官方计划人数

**为什么先用 01 而不是 03：** 01 是官方发布渠道的结构化采集，批次划分和计划数最准确。03 是二手整合可能有录入偏差。

### Step 3: Layer 3 · 填充分数数据

**目的：** 将 2022-2025 四年的录取分数填入 major.yearly

**数据源：**
1. 01/专业分数线_四川_2025 → yearly.2025（min/minRank/avg/avgRank/max/maxRank/enrolled）
2. 01/专业分数线_四川_2024 → yearly.2024
3. 01/专业分数线_四川_2023 → yearly.2023
4. 01/专业分数线_四川_2022 → yearly.2022
5. 01/院校分数线_四川_2025 → groupYearly.2025（filingMin/filingMinRank/groupEnrolled）
6. 01/院校分数线_四川_2024 → groupYearly.2024（batchMin/batchMinRank/batchEnrolled）

**匹配键：** 院校代码 + 科类 + 批次 + 专业代码

**注意：** 01 的批次名可能与 batch_tree 不同，需要批次名归一化。

### Step 4: Layer 3 · 网购数据补漏

**目的：** 用 03 网购数据补充 01 未覆盖的字段和记录

**补充的字段类型：**
- 专业评价（软科评级/排名、学科评估、专业水平、国家特色、专业排名、专业荣誉、硕博点）
- 老批次溯源（oldBatch/oldBatch2）
- 院校备注、专业备注
- 01 缺失的历史年份数据

**合入顺序：**
1. A 李老师专家版 (48135行, 70列) — 基表，最完整
2. H 清洗后修改 (48133行, 87列) — 列最多，有 25 年投档分
3. G 整合版 (47760行, 85列) — 与 H 结构相似，补遗漏
4. C 万能版0624 (47760行) — 不同供应商，交叉校验
5. B 专家版0624A (47760行) — 含分组文本块
6. F 曦鸿仕3月版 (45238行) — 最早版本，兜底补漏

**每张表合入时使用两级匹配策略（见下节）。**

## 两级匹配策略

### 第一级：精确匹配

**匹配键：** `院校代码 + 科类 + 录取批次 + 招生类别 + 专业组代码 + 专业代码`

6 字段全部命中 → 判定为同一条记录 → 逐字段合并：
- 目标字段为空 → 直接填入
- 目标字段已有值且与源值相同 → 跳过
- 目标字段已有值且与源值不同 → 写入冲突报告，不自动覆盖

### 第二级：置信度匹配

**触发条件：** 第一级未命中

**候选集范围：** `院校代码 + 科类 + 录取批次` 相同的所有记录

**匹配方法：** 拿源表待匹配行的**专业级全部字段**，与候选集中每条记录逐字段计算相似度：

| 字段类型 | 比较方法 |
|---|---|
| 字符串（专业名、全称、备注、专业类、门类…） | 文本相似度（编辑距离 / 模糊匹配） |
| 数值（计划人数、学制、学费、历年分数…） | 数值相等或接近度 |
| 代码（专业代码、专业组代码） | 精确匹配 / 近似匹配（差 1-2 位） |

全部字段加权汇总 → 取候选集中最高分作为最佳匹配。

**置信度阈值：**

| 分数 | 判定 | 处理 |
|---|---|---|
| ≥ 70 | 大概率同一条（如 OCR 识别导致代码偏差） | 合并，标记"置信匹配" |
| 30 - 70 | 存疑 | 写入冲突报告，人工审核 |
| < 30 | 大概率新增数据 | 新增记录 |

### 批次名归一化

所有数据源的批次名在匹配前先通过 `batch_mapping.py` 归一化到 batch_tree 的标准名称。无法映射的批次名写入异常报告。

## 冲突报告格式

```
conflict_report.csv:

院校代码 | 院校名称 | 科类 | 批次 | 专业代码 | 专业名称
字段名 | 当前值 | 新源值 | 来源表 | 匹配类型 | 置信度
差异类型: 数值偏差(≤3) | 数值偏差(>3) | 文本微调 | 文本不同 | 一方缺失

按差异严重程度排序，方便人工从最可疑的开始审核。
```

## 整合过程日志

每步记录：
- 源表名称、行数
- 精确匹配数、置信匹配数、新增数、冲突数
- 各字段填充率变化

最终汇总：
- 总记录数、各字段覆盖率
- 数据来源分布（每条记录的字段分别来自哪个源）
